## สิ่งที่ยืนยันได้

- เทียบ PDF ฉบับแก้ไขครั้งที่ 3 ลงวันที่ 3 กันยายน 2569 ครบทั้ง 3 หน้าอีกครั้ง
  ใช้เอกสารที่ผู้ใช้ให้เท่านั้น ไม่ใช้ข้อมูลทางการแพทย์จากอินเทอร์เน็ตหรือภาพ mockup
- มี 29 routes: เปิด 27 และปิด 2 ที่ต้นฉบับกำกวมเหมือนเดิม
- การเปลี่ยน routes.json รอบนี้เปลี่ยนเฉพาะ presentation ไม่มีการแก้ข้อความ
  ตัวเลข ชื่อยา แหล่งอ้างอิง เงื่อนไข หรือปลายทาง clinical routes
- คำตอบ 23 หัวข้อจัดเป็นการ์ดขาว/มิ้นต์ อีก 4 หัวข้อสั้นยังเป็นข้อความ
  ตัวอ่านข้อความจาก payload ยืนยันว่าการจัดบล็อกไม่ได้ตัด ย่อ หรือเรียงข้อความใหม่
  และ snapshot ของข้อความต้นฉบับยังเป็น baseline เดิม
- ตรวจทุก alias ทั่วไปและตามบริบทที่ลงทะเบียนไว้ กับ route ที่กำหนดไว้
  ตรวจว่าทั้ง 27 หัวข้อไปถึงได้จากปุ่มที่ renderer สร้างจริง ไม่ใช่เพียง graph ใน JSON
- ตรวจ webhook ลงลายเซ็น, ปุ่มผลบวก/ในเวลา/นอกเวลา, การถามต่อ เปลี่ยนหัวข้อ
  และกลับเมนูโดยไม่ติดบริบทเก่า รวมถึงชุดทดสอบ KV/กัน event ซ้ำเดิม
- เติมทางเข้าเมนูหลัก 6 หัวข้อได้แม้ยังไม่มี Rich Menu, รายงานเตือนก่อนเปิด
  Google Form พร้อม URL คัดลอกได้, ติดต่อใช้ข้อความรอข้อมูลเดิม ไม่แต่งชื่อหรือเบอร์
- รูป/ไฟล์/เสียงในแชท 1:1 ตอบข้อความไม่รองรับเดิมและทางกลับเมนู
  ไม่โหลดไฟล์หรือประเมินข้อมูลทางคลินิก; group/room และ event ที่ไม่มีรูปแบบรองรับยังข้าม

3. รายชื่อ/ช่องทางติดต่อยังไม่มีข้อมูลที่อนุมัติ จึงยังใช้ contact pending

   และไม่ใช่ระบบประเมินการรักษารายบุคคล
6. ตัวอย่างจัดวางในเครื่องไม่ใช่ LINE จริง; native Workers tests ใช้ตัวรับ HTTP
   จำลองที่ขอบเขต LINE API จึงยังไม่ยืนยันการรับ payload ของ LINE หรือหน้าตาบนมือถือ

## ข้อจำกัดหน้าตาและการทดสอบต่อ

Flex มีหัวข้อ แบ่งบล็อก เว้นระยะ และเลขลำดับเฉพาะที่ต้นฉบับมีเลข
ไม่มีการตัดเนื้อหาด้วย maxLines; ชื่อปุ่มบนการ์ดใช้ชื่อเต็ม
Quick Reply ที่ชื่อเกิน 20 ตัวอักษรไม่แสดงเป็นปุ่มลัด แต่ปุ่มชื่อเต็มยังอยู่บนการ์ด
ไม่สร้างชื่อย่อที่ทำเงื่อนไขทางคลินิกหาย

ยังไม่โฮสต์มาสคอตเพิ่มหรือแสดง PDF ให้ดาวน์โหลด ส่วน metadata อ้างอิงเก็บภายใน
ตาม spec ที่ไม่ให้ทำ source footer ใน MVP; Rich Menu เป็น Ticket 7 ไม่ใช่งานรอบนี้

หลังอนุมัติ push/deploy ให้ลองบน LINE มือถือด้วยข้อมูลสมมติ:

- พิมพ์ “เมนูหลัก” แล้วกดทั้ง 6 หัวข้อ
- กดการเจาะเลือด → ผล Positive อย่างน้อยหนึ่งตัว → ใน/นอกเวลาราชการ
  ตรวจว่าชื่อปุ่มเต็มอ่านได้ ไม่ถูกบีบหรือตัดจนเงื่อนไขหาย
- เปิดคำตอบยาวและกล่องเตือน partial ตรวจว่าข้อความไทยครบทุกบรรทัด
- เปลี่ยนหัวข้อ กลับเมนู และลองคำถามต่อที่ไม่มีบริบท
- กดรายงาน อ่านคำเตือน เปิดฟอร์มจริง และลองคัดลอก URL โดยไม่ส่งข้อมูลผู้ป่วย
- ส่งรูป/ไฟล์/เสียงทดสอบที่ไม่มีข้อมูลส่วนบุคคล ตรวจข้อความไม่รองรับ

สถานะ: งาน renderer ตรวจในเครื่องแล้ว ยังไม่ push/deploy การ์ดชุดใหม่นี้
