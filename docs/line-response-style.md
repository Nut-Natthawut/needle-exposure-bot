# LINE response visual reference

ผู้ใช้ยืนยันภาพอ้างอิงวันที่ 3 ตุลาคม 2569:
`assets/branding/line-chat-visual-reference.png`

## รูปแบบที่ต้องใช้ใน Ticket 6 และ 7

- การ์ด Flex Message พื้นสีขาว โทนมิ้นต์/เขียวอมฟ้า ตัวหนังสือเข้ม อ่านชัดบนมือถือ
- หัวข้อชัดเจน เว้นระยะพอดี; ขั้นตอนที่ต้นฉบับมีลำดับ แสดงเลขลำดับพร้อมสีช่วยแยก
- กรณีที่ต้องเลือก ใช้ปุ่ม postback/Quick Reply ที่ส่ง routeId จริง
- คำเตือนจาก ui.json แยกเป็นกล่องที่เห็นชัด ไม่สร้างคำเตือนทางคลินิกใหม่จากภาพ
- มาสคอตใช้พยาบาลผู้ชายที่เลือกแล้วใน assets/branding/male-nurse-line-avatar.png
- Rich Menu 6 ช่องใช้ภาษาและสไตล์สอดคล้องกับการ์ดคำตอบ
- clinical text ต้องรักษาข้อความใน routes.json ทุกตัวอักษร; แบ่งบล็อกเพื่อจัดภาพได้
  แต่ห้ามตัดเงื่อนไข เปลี่ยนคำ หรือใช้ข้อความทางการแพทย์ในภาพเป็นแหล่งอ้างอิง
- รูปเป็น reference ด้านรูปลักษณ์ ไม่ใช้ขั้นตอน/ตัวเลข/ชื่อโรงพยาบาลในรูปแทนข้อมูล PDF

## ขอบเขตของ LINE

จัดรูปภายใน Flex Message และ Rich Menu ได้ แต่ไม่ควบคุมพื้นหลังห้องแชท
เวลา/สถานะอ่าน หรือรูปทรง UI ของแอป LINE ให้เหมือน mockup ทุกจุด
ฟอร์มในโทรศัพท์ด้านขวาเป็นภาพตัวอย่าง: MVP แสดงการ์ดเตือนและปุ่มเปิด Google Form
ไม่สร้างช่องกรอก HN/ข้อมูลผู้ป่วยใน Flex Message และไม่เก็บข้อมูลฟอร์มผ่าน Worker

## เกณฑ์ตรวจตอนทำ renderer

- ทดสอบทั้งคำตอบสั้น/ยาวและการขึ้นบรรทัดไทยบน LINE มือถือจริง
- ปุ่มทางเลือกไม่ทับข้อความและส่ง route ที่ตรงกับข้อความบนปุ่ม
- คำตอบที่เป็น partialRouteIds แสดงคำเตือนข้อมูลบางกรณียังไม่พร้อม
- content snapshot ของ renderer ต้องยืนยันว่า layout ไม่แก้ข้อความคลินิก

## สถานะ Ticket 6 (11 ตุลาคม 2569)

ทำการ์ดขาว/มิ้นต์ หัวข้อ ขั้นตอนเป็นเลข และกล่องเตือนจาก UI copy แล้ว
ปุ่มใช้ชื่อเต็ม; ชื่อที่เกินข้อจำกัด Quick Reply ยังอยู่บนการ์ด ไม่ตัดคำให้สั้นลง
มาสคอตยังใช้รูปโปรไฟล์ที่เลือกไว้ ไม่สร้าง URL รูปสาธารณะเพิ่มในรอบนี้
Rich Menu ยังรอ Ticket 7; การ์ดใหม่ยังไม่ได้ deploy และยังต้องตรวจบน LINE มือถือจริง

## ปรับหน้าตาเฉพาะส่วนแสดงผล (16 ตุลาคม 2569)

ผู้ใช้อนุมัติแนวสะอาด สุขุม เป็นมิตร: ขาว–เขียวเข้มเป็นหลัก มิ้นต์เป็นสีเสริม
รอบนี้ปรับ Flex เดิม ไม่เปลี่ยน Rich Menu ที่อัปโหลดใน OA Manager

- หัวการ์ดเขียวเข้ม/ตัวอักษรขาว ใช้รูปแบบร่วมกันทั้งคำตอบ เมนู และตัวเลือก
- เนื้อหาพื้นขาว ไม่ย่อหรือตัดข้อความ เพิ่มระยะระหว่างบรรทัดที่ wrap เป็น 6px
- พื้นที่ปุ่มแยกด้วยพื้นสีอ่อน ปุ่มทางถัดไปใช้มิ้นต์ ปุ่มกลับเมนูเป็น link style
  เปลี่ยนเฉพาะหน้าตา ไม่เปลี่ยน action, label, URL, ลำดับ หรือ Quick Reply
- คำเตือนรายงานใช้กล่องชมพูอ่อน/ตัวอักษรแดงเข้มแบบเดียวกับ partial warning
  คงข้อความเดิม ปุ่มเปิด Google Form และ URL คัดลอกได้เดิม
- ไม่แก้ clinical corpus, UI copy, aliases, source metadata หรือสถานะ route
  ประเด็นข้อมูลติดต่อที่ไม่สอดคล้องกันพักไว้รอถามลูกค้าตามคำสั่งผู้ใช้
- ลิงก์ D ที่เปิดฟอร์มตรงและ F ที่เปิดเว็บคลินิกใน OA Manager ไม่ถูกเปลี่ยน

ตรวจในเครื่องด้วย tests และการเทียบข้อความ/คำสั่งปุ่มก่อน–หลัง ไม่ใช่หลักฐานว่า
LINE มือถือทุกขนาดหน้าจอหรือการตั้งค่าฟอนต์แสดงผลสมบูรณ์ ต้องตรวจจริงหลัง deploy
ยังไม่มี commit, push, deploy หรือการแก้ตั้งค่า LINE จริงในรอบนี้

## ข้อความสนทนาและการยืนยันหัวข้อ (16 ตุลาคม 2569)

ใช้คำทักทายที่ผู้ใช้เลือก: “สวัสดีครับ ผมเป็นบอตเข็มทิ่มตำ NKP” แล้วขึ้นบรรทัดใหม่
“เลือกหัวข้อที่อยากดูจากเมนูด้านล่างได้เลยครับ” แสดงพร้อมเมนูเมื่อทักทายหรือเปิดเมนูหลัก
ไม่แปะคำทักทายนำหน้าคำตอบทางคลินิก คำขอบคุณและข้อความเมื่อไม่เข้าใจเป็น UI copy แยกกัน
Humanizer ใช้เกลาข้อความเหล่านี้ระหว่างพัฒนา ไม่ใช้แก้ข้อมูลใน `routes.json`
และไม่มีการเรียก AI ระหว่างตอบแชท

คำพิมพ์ใกล้ชื่อหัวข้อที่รองรับ เช่น “เจาะเลืด” ได้รับคำถาม “หมายถึงการเจาะเลือดใช่ไหมครับ?”
พร้อม Quick Reply “ใช่ ดูหัวข้อนี้” และ “เลือกหัวข้ออื่น” จนกว่าจะกดปุ่มยังไม่แสดงคำตอบคลินิก
ชื่อหัวข้อมาจากรายการที่กำหนดไว้ ไม่ทวนข้อความดิบของผู้ใช้ ไม่เสนอแก้ผลตรวจ เวลา ชื่อยา
รหัสหรือตัวเลขแทนผู้ใช้ และไม่เปลี่ยน Rich Menu/ลิงก์ D/F ที่เจ้าของตั้งไว้

รองรับคำลงท้ายสุภาพและเครื่องหมายท้ายที่กำหนดร่วมกับคำค้น เช่น “เจาะเลือดครับ!”
หรือ “เจาะเลืดครับ?” รวมถึงตัวพิมพ์อังกฤษเล็ก/ใหญ่ เช่น “pep” แต่ไม่ตัดคำปฏิเสธ
เงื่อนไข หรือตัวเลขออกจากประโยคเพื่อให้จับคำได้ ผลตรวจและเวลาที่พิมพ์ยังต้องอาศัย
บริบทที่ถูกต้อง คำตอบทั้งหมดเป็นชุดเดิม ไม่ได้เพิ่มความสามารถวิเคราะห์ทางคลินิก
