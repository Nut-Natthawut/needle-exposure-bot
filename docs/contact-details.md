# ช่องทางติดต่อผู้เกี่ยวข้อง

ข้อมูลต้นทาง: ผู้ใช้ส่งในแชทวันที่ 20 ตุลาคม 2569 เพื่อแทนข้อความรอข้อมูลติดต่อเดิม

| หน่วยงาน | หมายเลขที่ผู้ใช้ให้ |
| --- | --- |
| งานป้องกันและควบคุมการติดเชื้อในโรงพยาบาล | 1178 / 9270 |
| ห้องตรวจอาชีวเวชกรรม | 9274 |
| ห้องฉุกเฉิน | 1105 / 1106 / 9269 |

ผู้ใช้ยืนยันเพิ่มเติมว่าข้อมูลเป็นหมายเลขหน่วยงานที่ได้รับมา และขอปุ่มเลือกเบอร์เพื่อเปิดแอปโทรศัพท์
บอตแสดงชื่อหน่วยงานและหมายเลขตามต้นทาง พร้อมปุ่ม `โทร 1178` ฯลฯ ภายในแต่ละกลุ่ม
แต่ละปุ่มเป็น URI action `tel:` เช่น `tel:1178` โดยใช้ตัวเลขเดิม ไม่เติมเบอร์หลัก/รหัสพื้นที่
ไม่ติดป้าย “เบอร์ภายใน” ไม่เพิ่มเวลาทำการ และไม่แสดงคำเตือนว่าข้อมูลจากหน่วยงานผิด
การยืนยันโทรขึ้นกับแอปโทรศัพท์/ระบบของเครื่อง ไม่ใช่ LINE Call และบอตไม่ได้โทรแทนผู้ใช้

## ผลตรวจและขอบเขตข้อมูล

- การตรวจเว็บก่อนหน้านี้พบ 9274 ตรงกับ [หน้าอาชีวเวชกรรมของโรงพยาบาลนครพิงค์](https://www.nkp-hospital.go.th/th/department/occupational/clinic-3.php)
  ข้อมูลหลักที่ใช้ทำปุ่มยังคงเป็นชุดที่ผู้ใช้ได้รับจากหน่วยงาน ไม่ใช้ผลค้นหาแทนข้อมูลนั้น
- ข้อมูลที่แสดงในบอตยึดชุดที่ผู้ใช้ให้ ไม่ได้นำเบอร์หลัก อีเมล เวลา หรือข้อมูลอื่นจากเว็บมาเพิ่ม
- ข้อมูลนี้เป็น UI contact copy ใน `content/ui.json` ไม่ใช่ clinical route และไม่แก้เอกสารแนวทาง
- แสดงเป็น Flex card เดียวจากโทนเดิม แยก 3 กลุ่มหน่วยงาน/6 ปุ่มโทร พร้อมปุ่มกลับเมนูหลัก
  ไม่มีการเลือกหน่วยงานให้ตามกรณีทางการแพทย์
- ใช้ [URI action ที่ LINE รองรับ](https://developers.line.biz/en/docs/messaging-api/actions/#uri-action)
  การตรวจ payload ในเครื่องไม่ใช่การโทรจริง ต้องลองกดเปิดแอปโทรศัพท์บน LINE มือถือ

## Rich Menu ช่อง F ที่ตั้งเอง

โค้ดรองรับ postback `ui.contact` และข้อความ `ติดต่อผู้เกี่ยวข้อง` อยู่แล้ว
แต่การแก้โค้ดไม่เปลี่ยน Rich Menu ที่ตั้งใน OA Manager ให้อัตโนมัติ
หาก F ยังเป็นลิงก์คลินิกพรีเมียม หลัง deploy ต้องเปลี่ยนประเภทเป็น **ข้อความ**
ใส่ `ติดต่อผู้เกี่ยวข้อง` แล้วบันทึก จากนั้นกด F บน LINE มือถือเพื่อตรวจข้อมูลครบทั้งสามหน่วยงาน
ไม่ต้องรันตัวติดตั้ง Rich Menu ผ่าน API ซึ่งอาจทับการตั้งค่าช่องอื่นของเจ้าของ
